# Qask 用户指南

Qask 将多个 AI 官方网页放在一个桌面工作区中。适合把同一问题同时交给多个模型，再查看和比较各自的回答；输入框右侧的“对比”会把各面板最新回答并排展示，并可让一个模型总结差异。当前产品只提供网页模式，不提供 API 配置或 API 请求。

## 启动与登录

在**完整源码仓库 checkout** 的项目目录执行：

```bash
npm ci
npm start
```

应用启动后，每个面板都会打开一个模型网站。请在每个网站内自行登录。各内置模型使用独立的本地 Electron 分区，登录状态通常会在下次启动时保留。

本机 macOS arm64 已验证 `npm ci` 后可启动 Qask。如果换机后启动报 `spawn ENOEXEC` 或 Electron 路径为 `electron.exe`，说明依赖来自 Windows；请删除 `node_modules` 后在目标 macOS 本机重新运行 `npm ci`。`npm pack` 的最小运行时包不包含 lockfile 或测试资产，不适用这套开发验证流程。

## 选择工作区布局

侧栏提供四种布局：

- 单窗口：集中使用一个模型。
- 双窗口：最适合直接比较两个模型。
- 三窗口：同时参考三个模型。
- 四窗口：以 2×2 网格查看四个模型。

也可使用 `Alt + ←` 和 `Alt + →` 依次切换布局（可在设置中改为 `⌘/Ctrl + Alt + ←/→` 或关闭；仅在 Qask 自身界面获得焦点时；焦点在网页面板内时请用侧栏布局按钮）。折叠侧栏后，布局按钮仍会显示在窄工具栏中。

## 外观主题

侧栏“外观”提供三种模式：

- **系统**（默认）：跟随 macOS 的浅色/深色外观；
- **暗色**：始终使用 Qask 暗色界面；
- **亮色**：始终使用亮色界面。

主题会保存在本机，并通过 Electron 的 `nativeTheme` 同步给网页面板：支持深色模式的网站（例如使用 `prefers-color-scheme` 的站点）会跟随切换；不支持深色模式的网站仍使用它自己的配色，这是网站自身的限制，Qask 不会强行反色破坏页面。

## Windows 版本

Qask 可以用 `npm run package:win` 从 macOS 交叉打包 Windows x64：

- `Qask-<版本>-win-portable-x64.exe`：便携版，双击运行，不安装；
- `Qask-<版本>-win-setup-x64.exe`：安装程序，可选择安装目录。

Windows 构建未签名，SmartScreen 可能提示；目前主要在 macOS 验收，Windows 真机请先用干净配置测试。Windows 上附件目录为“图片\Qask Attachments”，截图目录为“图片\Qask Screenshots”；快捷键中的 `⌘` 在 Windows 上对应 `Ctrl`。

## 设置

侧栏底部的「设置」按钮（折叠后是齿轮图标）可以打开设置：

- **快捷键**：发送消息（Enter / ⌘/Ctrl + Enter / Ctrl + Enter）、切换布局、打开回答对比都可配置或关闭；`⌘/Ctrl + ,` 打开设置；`Shift + Enter` 始终换行；快捷键不会在输入框内触发。
- **主题**：跟随系统、暗色或亮色，和侧栏外观切换保持同步。
- **默认发送方式**：立即发送、排队发送或仅填入。这里修改后，底部发送按钮会立即同步；在发送按钮悬停菜单里切换模式也会保存为新的默认值。
- **对比默认模型**：打开回答对比时优先选择这个模型生成差异总结；选「自动」时使用当前布局第一个可用面板。如果默认模型未打开，会自动回退。
- **发送 AI 总结前再次确认**：默认开启。关闭后点「AI 总结差异」会直接把已读取的回答发送给所选模型，不再弹出确认；回答可能包含敏感内容，请谨慎关闭。
- **底部状态栏**：默认隐藏。开启后，启动、发送、队列、错误等状态会显示在输入框上方；`⌘/Ctrl + /` 查看快捷键帮助时会临时显示。
- **数据与登录**：登录状态由各网站保存在本机持久化分区，Qask 启动时不会清除。正常重启不需要重新登录；如果网站主动让 session 过期、要求二次验证，或你清理了本地数据，仍需重新登录。可以点「打开本地数据目录」查看 Qask 的本地存储位置。
- **关于**：显示 Logo、版本、AGPL 许可，以及开源仓库 [github.com/CYK16688/Qask](https://github.com/CYK16688/Qask) 和 Releases 链接。

设置保存在本机，重启后保留。

## 发送方式与队列

鼠标悬停在底部发送按钮上，会展开三种发送方式：

- **立即发送**（默认）：马上发送，之后手动输入下一条；
- **排队发送**：把当前输入加入队列；等所有真正开始回答的面板完成后，自动发送队列里的下一条；
- **仅填入**：只把文字填进各网页输入框，不点击网页的发送按钮，适合想逐站确认的场景。

发送按钮右下角的小圆点表示当前不是“立即发送”：紫色为排队，琥珀色为仅填入。

### 排队发送怎么判断“回答完成”

队列发送分两步：

1. **先等当前回答结束**：如果加入队列时还有面板正在回答上一条消息，Qask 会先等这些面板的“停止生成/Stop”按钮消失、回答文本稳定下来，再发送队列里的下一条；
2. **再等这条消息的回答结束**：发送后轮询各面板的最新回答文本，文本不再变化（约 2 秒内稳定；如果仍检测到停止按钮则多等一轮）即视为完成。

所有已成功自动发送的面板都完成后，队列立刻发送下一条。这个判断是启发式的：如果某个网站不暴露停止按钮或回答文本，Qask 会在重试几次后继续，或在 **3 分钟** 超时后跳过等待，避免队列永久卡住。

队列面板会显示当前正在等待哪些面板，并提供：

- **跳过等待**：不等当前回答，直接发下一条；
- **清空**：移除还没轮到的排队消息（正在发送/等待的当前条继续）。

还没轮到的消息可以管理：

- **拖动左侧手柄**重新排序；也可以聚焦该行后按 `Alt + ↑/↓` 移动；
- **点铅笔编辑**，`Enter` 保存，`Esc` 取消，`Shift + Enter` 换行；
- **点 × 删除**该条消息。

正在发送/等待回答的当前条会锁定，不能拖动、编辑或删除，避免和正在发送的网页内容错位。排队最多 20 条，只支持纯文本，暂不支持附件；队列只保存在内存里，退出应用后清空。

## 选择模型网站

“模型网站管理”列表的顺序就是工作区的自动排序。只需拖动每行左侧的握柄即可调整顺序。当前布局使用的前 N 个网站会以紫色边框和背景色突出显示：三面板时即为前三个。排序后，已有网页会直接移动到新的面板位置，不会为了排序而刷新；只有新进入当前布局、尚未打开的网站才会加载。登录状态、草稿、滚动位置和正在生成的回答会随网页一起保留。

每行右侧都有删除按钮，内置网站和自定义网站都可以移除；删除内置网站会记录在本地，侧栏底部会出现“恢复默认网站（N）”按钮，可随时恢复，不需要清除应用数据。要更换当前布局中的网站，请拖动侧栏“模型网站管理”列表。默认网站包括：

- ChatGPT
- Gemini
- 豆包
- Claude
- Copilot
- DeepSeek
- Kimi

面板标题栏、刷新、缩放和面板内模型切换控件均已移除，全部区域用于网页阅读与对话。三、四面板仍会在页面加载后自动使用适合密度的原生网页缩放。

## 添加自定义网页模型

1. 在“模型网站管理”中点击“添加模型”。
2. 填写名称和完整的 `https://` 地址。
3. 默认保持“仅填入内容”；只有勾选明确的信任选项，才允许 Qask 对该**精确网站 origin**自动发送文本。
4. 确认后，该网站会出现在侧栏的“模型网站管理”排序列表中；将它拖入当前布局的前 N 名即可打开。

自定义网站使用通用策略，不保证适配每个网站。默认请在网页中检查内容后手动发送。Qask 不会自动打开第三方弹窗或下载文件；若网站依赖外部 OAuth 弹窗，当前可能无法在 Qask 内完成登录。

## 同时发送问题

1. 在底部输入框输入问题。
2. 按当前发送快捷键（默认 `Enter`）或点击发送按钮。
3. Qask 会同时向当前活动面板执行同一轮操作；已打开的网页和各自的登录/对话上下文会保留。只要网页处于可发送状态，就可以不限轮次地继续发送下一轮、第三轮及后续消息，Qask 不会因每轮消息重新加载网页。

输入框会随内容扩展到固定上限，超过后在输入框内滚动，不会持续挤占网页区域。附件、录音和发送按钮保持在输入框右侧。发送按钮只会在有文字或附件且未录音、未发送时启用。`Shift + Enter` 用于换行；使用中文、日文等输入法选词时，`Enter` 只确认候选词，不会发送。

输入框上方是本地状态条：它会显示页面加载、逐面板发送结果、等待超时、附件保留和录音错误等 Qask 自己生成的消息，最新 8 条按时间排列，可用右侧 `×` 清除。状态条只显示本地文本，不会把第三方网页内容回显到宿主界面。

持续多轮发送时，网页内部的普通加载活动不会把已就绪面板误判为未就绪。每个网页仍必须完成真正的主页面跳转后才能接收下一轮；单个网页上一轮注入仍未结束时，Qask 会跳过该网页以避免旧消息晚到覆盖新消息，其余可用网页仍会继续接收新一轮。该网页的旧注入结束后，会在下一次后续发送中重新加入；它不会被永久排除。

若某个面板加载失败或页面进程退出，面板上会出现“重新加载”按钮；重新加载只重建该网页，不会清空其登录分区或其它面板。

发送依赖各网站当前的 DOM 结构和登录状态。Qask 的“已尝试触发网页发送”不等同于网站已经接受请求，也不等同于模型已经生成回答；“已填充输入框”表示需要在对应网页确认或手动发送。若你在上一轮尚未结束时改写了底部草稿，Qask 会保留新草稿，不会被上一轮完成动作清空。请以每个网页面板实际显示的内容为准。

## 回答对比

点击输入框右侧的“对比”打开回答对比视图。它会读取当前活动面板中可见的最新回答，按面板并排展示：

- **同步滚动**：默认开启，滚动任意一栏时其它栏按相同比例跟随；可以在工具栏关闭。
- **刷新回答**：重新读取各面板的最新内容；视图打开时也会每 4 秒自动刷新一次。
- **AI 总结差异**：从“总结模型”中选择一个已就绪、允许自动发送的面板，点击后 Qask 会把各面板回答整理成对比提示词，发送给该模型，并把它的总结显示在下方。发送前会弹出确认，因为回答内容可能包含敏感信息。
- 对比读取是**尽力而为**的：不同网站的页面结构会变化，如果某一栏提示“未找到回答区域”，请先确认该面板已完成回答，再点“刷新回答”；原始网页面板始终是准确来源。
- 读取到的回答只保存在当前应用内存中，关闭应用即消失，Qask 不会写入本地文件或导出。

## 附件、图片与语音

- 点击输入框左侧 `+` 可选择图片、音频或 PDF：最多 5 个、合计 20 MB；单张图片最多 5 MB，单个音频/PDF 最多 10 MB。
- 将图片粘贴到输入框也会加入附件列表；Qask 会把粘贴的图片保存到 `~/Pictures/Qask Attachments/`，以便在网站自己的上传界面中选择。
- 点击麦克风按钮后，Qask 只会录制本地音频；录制最长 2 分钟，停止后会写入 `~/Pictures/Qask Attachments/` 并以音频附件加入列表，可在网站上传界面选择。取消录制不会写入任何文件。
- 附件列表中的“已保存”表示文件已在本机；点击“显示”会在 Finder 中定位该文件。“磁盘文件”表示它来自你选择的磁盘文件，可在网站上传界面重新选择。
- 录音尚未停止或仍在申请麦克风权限时，Qask 会暂缓发送；先停止或取消录音，待它成为附件或被丢弃后再发送。
- 首次录音时 macOS 会请求麦克风权限。拒绝后，请在“系统设置 → 隐私与安全性 → 麦克风”允许 Qask，然后重新启动应用。
- Qask 不会把附件交给第三方网页脚本，也不会在带附件时填入文字、点击发送或模拟粘贴。
- 带附件时，Qask 会把文件和草稿保留在本地，并提示你在每个目标网页自己的可见上传界面中选择文件、确认预览并手动发送。
- Qask 不会把网页 DOM 状态当作上传成功或模型已经读取附件的证明。
- 附件队列只在当前应用会话中保留；录音和粘贴图片写入 `~/Pictures/Qask Attachments/` 后，移除附件或退出 Qask 不会自动删除这些文件，需要时请自行清理。附件队列不会写入 `localStorage`。

第三方网站的账户套餐、当前模型、文件限制和页面结构均可能导致附件被拒绝。若没有显示附件，请直接使用该网站自己的上传操作。

## 数据保留

Qask 当前使用浏览器 `localStorage` 保存：

- 布局选择；
- 模型网站排序；
- 自定义网页模型；

附件队列和麦克风授权状态不会写入 `localStorage`；录音与粘贴图片会按上述规则保存到 `~/Pictures/Qask Attachments/`。清除应用数据会清除 Qask 设置和网页登录状态，但不会删除该文件夹。

## 本地数据与 GitHub 信息

Qask 不包含 Git 或 GitHub 集成：不会扫描、读取或上传本地仓库、`.git`、Git 配置、remote、GitHub CLI 配置、Git 凭据、SSH 密钥、Cookie、环境文件或剪贴板历史。它不会自动从文件夹、桌面、截图或项目中挑选附件。

只有你明确提交的输入文本才会由 Qask 尝试填入当前第三方网页。明确选择的图片、音频或 PDF 会保留在 Qask 本地，供你在目标网站自己的上传界面中另行选择。为降低误选风险，Qask 会在主进程验证所选磁盘文件，并拒绝隐藏文件、`.git`、受保护凭据目录、Qask 会话目录和明显含 GitHub/凭据名称的附件。请不要把任何机密交给第三方网站；Qask 无法控制网站对你自行上传内容的保存或处理。完整说明见 [PRIVACY.md](../PRIVACY.md)。

## 已知问题

- 网页适配器依赖第三方页面结构，Gemini 或其他网站改版后可能需要更新发送脚本；自动化测试只能检查脚本语法，不能保证第三方网页接受发送。
- 已实现的是“本地录音 + 本地附件队列 + 可上传的本地文件”，不是统一的实时语音对话、语音转写或跨网站可靠上传。每个网站的实际附件能力需要由用户在登录后的网页上传界面中手工使用。
- 回答对比依赖各网站当前 DOM 的“最后一条回答”识别，网站改版时可能读取失败或读到不完整内容；此时请直接看原网页面板。
- AI 总结需要把回答内容发送给所选模型的网页；确认前请勿包含不希望交给该模型的信息。
- 站点页面结构变化可能导致某一模型的自动填入或自动发送失效。
